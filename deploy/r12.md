
## 14.10 第十二轮：抢答计分 / 无时限误判 / 聊天室与后台体验

本轮 10 项，其中两项属于**致命缺陷**（抢答题计分错误、刚进考场即提示时间已结束）。

### ① 抢答题分数全错（致命）

**现象**：抢答题环节各队分数不对，逻辑存疑。

**根因（两处叠加）**：

1. **速度排名从未生效**。`scoringService.speedRankingBonus()` 早已实现「按答对队伍提交时间排序，前 N% 得分」，但**全项目没有任何地方调用它**——它只是被导出，属于死代码。而 `scoreQuestion()` 对「答对」一律返回该题满分。结果是：抢答环节每支答对的队伍都立刻拿到满分，谁先按铃完全不影响得分，抢答形同虚设。

2. **缺少结算步骤**。按设计（7.3），抢答分数必须在「所有队伍提交后」才结算。旧实现没有这个环节，自然也就无从应用百分比名额。

**修复**：新增 `examService.settleSpeedRanking(stageId, cfg)`，在交卷汇总前执行：

- 仅对 `timeConfig.speedRanking = true` 的环节生效；
- 按题分组，取出该题所有 `is_correct = 1` 的记录，按 `submit_order` 升序排列；
- 调用 `speedRankingBonus()` 计算名额（前 `speedRankingPercent`%，`speedRankingRoundUp` 决定进位方式），命中者记该题满分，其余答对者记 **0 分**（抢答慢了不得分）；
- 答错的扣分保持不变（扣分与速度无关）；
- 同一队伍同一题的重复记录只取最早一次；
- 函数**幂等**，重复调用结果一致。

**过程中发现并修掉的第二个坑**：`speedRankingBonus()` 读取的是 camelCase 的 `teamId`，而数据库行给的是 `team_id`。直接传原始行会让 Map 的键全部变成 `undefined`，表现为「结算跑了但所有队伍都是 0 分」。现已显式转换。

**验证**：3 支队伍依次答对同一题（满分 4 分，前 50%），结算后第 1、2 队各得 4 分，第 3 队 0 分。

### ② 刚点进考试就提示「答题时间已结束，无法继续作答」（致命）

**现象**：明明刚进入考试，就被拒绝作答。

**根因**：`remainingSeconds()` 用 `timeConfig.totalTime` 作为整体时限。而抢答题等环节的总时长配置为 **0**（它们按 `perQuestionTime` 单题计时）。`limit = 0` 时算出 `remaining = max(0, 0 - elapsed) = 0`，于是 `expired = true`，`submitAnswer` 立刻抛出「答题时间已结束」。

**修复**：

- 后端 `remainingSeconds()`：`limit <= 0` 直接返回 `expired: false, unlimited: true`，无整体时限的环节永不判超时；
- 前端 `startTimer()`：总时长为 0 时不启动整体倒计时，只跑单题倒计时，避免误触发自动交卷；
- 前端 `load()`：原先写的是 `startTimer(data.availableTime || 600, ...)`——**0 会被 `||` 兜底成 600**，界面凭空多出一个 10 分钟倒计时。改为读取服务端 `timeLimit`，0 就是 0；
- 顶部「总时长」只在 `totalTimeLimit > 0` 时渲染。

**验证**：`start` 返回 `expired = false`、`timeLimit = 0`、`perQuestionTime = 90`，且可正常提交答案。

### ③ 所有赛事环节的队伍总榜分数都是 0

**现象**：个人榜分数正确，队伍总榜恒为 0。

**根因**：`getRanking()` 用 `SELECT team_id, student_id, total_score FROM stage_scores` 建表，键为 `teamId + '|' + (student_id || '')`，随后却以 `scoreMap.get(teamId + '|')` 取值。而 `stage_scores` 的每一行**都带具体学号**（`student_id` 从不落 NULL），键 `teamId|` 永远不存在 → 队伍分数恒为 0。同时 `liveMap` 只在 `scores.length === 0` 时才构建，有数据时反而为空。

**修复**：改为 `SELECT team_id, SUM(total_score), SUM(total_time) ... GROUP BY team_id`，键直接取 `String(team_id)`；`liveMap` 改为**始终构建**；取值用 `row !== undefined` 判断。个人榜逻辑本就正确（精确匹配 `teamId|studentId`），未改动。

**验证**：3 名队员各答对 3 题各得 6 分，队伍总榜 = 18，个人榜三人各 6 分。

### ④ 跳过的题目不在错题本中展示

**现象**：同学反馈跳过的题目在错题本里看不到。

**核实**：后端 `getWrongBook()` **已经**把「卷面上有、但没有任何作答记录」的题作为跳过项返回，并打上 `skipped: true`。问题出在**展示层**——跳过项与答错项外观完全一致，只靠「你的答案：未作答」一行小字区分，容易被忽略。

**修复**（前端 `StageWrong.vue`）：

- 跳过项增加独立的「未作答」标签（`warning` 色）；
- 概要区在错题数之外，单独显示「未作答」数量；
- 空状态文案改为「恭喜，本环节没有错题，也没有跳过的题目」。

### ⑤ 答题卡旁的榜单应可切换「三人相加 / 各自展示」

**要求**：答题过程中答题卡旁的榜单需要支持合并（三人相加）与分开两种展示，并在管理后台提供切换。

**实现**：新增环节配置项 `rankBoard`（默认 `auto`）：

| 取值 | 含义 |
| --- | --- |
| `auto` | 跟随赛制：团队环节看队伍总榜，个人环节看个人榜 |
| `merged` | 固定队伍总榜（全队三人分数相加，一个队伍一行） |
| `separate` | 固定个人榜（每位队员一行） |

- 后端 `stageConfig` 归一化该字段并下发；`examController.resolveBoard()` 的优先级为 **显式 `?board=` > 环节 `rankBoard` > 赛制推断**；
- 管理后台「环节编辑」新增「答题卡旁榜单」单选（跟随赛制 / 队伍总榜 / 个人榜）；
- 前端答题页 `currentBoard()` 读取该配置；标题随榜单切换为「队伍总榜」或「个人榜」；**高亮自己**的判断也从「环节赛制」改为「当前榜单类型」——否则个人环节切成队伍总榜后，`studentId` 比对永远匹配不上。

### ⑥ 聊天室支持自定义房间码

**实现**：

- 后端新增 `chatService.assertCustomCode()` / `setInviteCode()`：房间码必须为 **6 位数字**且全平台唯一，设置后有效期重新计算 24 小时；
- `POST /chat/rooms/:id/invite` 增加可选 `code`：传入则用自定义码，不传则随机重生成（兼容原行为）；
- 前端侧栏「房间码」区新增「自定义」按钮与弹窗；保存后同步更新本地 `chat_session.inviteCode`，否则题库检索的访客身份会失效。

### ⑦ 题目发送到聊天室时直接带出答案

**根因**：`sendIncomingQuestion()` 早已把 `answer` 放进消息 `extra`，但聊天室的**题目卡片模板只渲染题干与选项，从未渲染 `answer`**。

**修复**：题目卡片新增「正确答案」行，正确选项同时高亮；`extra` 额外携带 `analysis`，有解析时一并展示。

### ⑧ 聊天室回车发送无效 / 变成换行

**根因**：绑定 `@keydown.enter.exact.prevent` 在 `el-input` 上。Element Plus 内部包了一层 `textarea`，部分浏览器下事件不按预期冒泡；且 `.exact` 要求「没有其他修饰键」，中文输入法确认候选词时的回车也会命中。

**修复**：改为显式 `onDraftKeydown(e)`：非 `Enter` 直接返回；`isComposing` / `keyCode === 229`（输入法组合态）返回；带 `Shift` / `Ctrl` / `Alt` / `Meta` 返回以保留换行；其余情况 `preventDefault()` 后发送。

### ⑨ 管理后台排序按钮无反应

**核实**：综合平台资源管理页**原本没有任何排序按钮**——分类只能靠手输数字，网站列表也没有调整入口，用户所说的「按了没反应」实为功能缺失。

**修复**：

- 资源分类列表每项新增「上移 / 下移」，走已有的 `POST /resources/categories/reorder` 整体重排，避免逐个提交产生中间态；
- 网站列表新增「排序」列（减小 / 增大按钮），直接调整 `sort_order` 并即时刷新。

### ⑩ 资源分类禁止改名 / 删除，聊天室禁止删除

**实现**：

- 后端 `updateCategory()`：传入的名称与现有名称不一致时返回 403「资源分类名称不允许修改」；SQL 也不再写 `name` 列；
- 后端 `removeCategory()`：一律返回 403「资源分类不允许删除，如需下线请将状态改为禁用」（该分类的外键为 `ON DELETE CASCADE`，误删会连带清空其下网站）；
- 前端分类弹窗在编辑态把名称输入框置灰并提示「分类名称创建后不可修改」；
- 聊天室：**本就没有删除路由**，已确认无需改动。

### ⑪ 清空队伍答题数据支持选择环节与批量

**实现**：

- 后端原本已支持 `clear-answers` 传 `stageId`（缺省清空全部环节），本次补齐前端；
- 新增 `GET /api/stages/options`：返回全部环节（含所属赛事名，便于区分同名环节）。路由必须注册在 `/:id` **之前**，否则 `options` 会被当成 id；
- 队伍管理页「清空答题」改为弹出对话框：显示清空对象（支持多选队伍批量），可选择「指定环节」（**多选**）或「全部环节」，二次确认后逐队逐环节清空，最后汇总提示「答题 / 成绩 / 抽题快照 / 预警」条数。
